# OpenTale Demo

一个可以离线验证的共同生成叙事实验：多个叙述位置共同使用表达，各自保留不同的归属与作用；一处的变化实际改变别处下一次生成的条件，呈现位置再从这些关系中形成一条可读序列。

主仓库仅为本目录。系统用确定性的运行内核管理关系与续延，用可替换的模型生成内容。默认 `fixture` 完全离线，不需要 API key。离线样例验证机制，不能证明真实模型的语义耦合、审美或文学效果。

## 启动

目前面向 macOS / Linux；预设存储使用 POSIX 文件描述符与 `fcntl` 文件锁，不宣称支持 Windows。需要 [uv](https://docs.astral.sh/uv/) 和 Node.js 20+（含 npm）；源码要求 Python 3.11+，项目固定使用 Python 3.13。启动脚本缺少该版本时允许 uv 将解释器下载到本仓库 `.toolchain/python`，依赖与缓存也保留在本仓库。命令从仓库根目录执行：

```sh
python3 scripts/bootstrap.py
uv run python scripts/dev.py build
uv run python scripts/dev.py serve
```

打开 <http://127.0.0.1:8231>。生产网页与 API 由同一个后端进程提供，只监听本机。端口被占用时可使用 `serve --port 8232`。

独立于当前终端运行：

```sh
uv run python scripts/dev.py detach
uv run python scripts/dev.py status
uv run python scripts/dev.py stop
```

`detach` 自动在缺少产物时构建网页，在 `runtime/` 保存私有进程记录和启动日志；`stop` 检查进程身份后再停止，保留所有存档。运行中的本机程序不因关闭 Codex 而退出；操作系统重启后需重新启动。

受限沙箱可能不允许监听回环端口或检查进程身份。脚本会明确报告权限限制；无法验证身份时保留记录并拒绝停止，请在有相应权限的本地终端执行。

生产服务不自动重载源码。更新代码后先重新构建，再 `stop` / `detach`；只有配置参数使用网页重新加载。

前后端分别开发时，在两个终端执行：

```sh
uv run python -m uvicorn opentale.api:app --host 127.0.0.1 --port 8231 --reload
```

```sh
cd frontend
npm run dev
```

开发网页使用 <http://127.0.0.1:5196>，代理 `/api` 至后端 8231。运行时快照、事件与进程记录均在忽略的 `runtime/` 中；删除指定对局会删除该对局的数据库记录，网页会要求明确确认。当前没有自动备份；导出副本由用户管理。

## 第一轮离线实验

网页创建 `letters` 预设，选择 **离线 fixture**，先运行一个窗口。随后查看：

1. 正文阅读区的一段呈现，与人物位置各自形成的内容。
2. 关系及诊断区的共享表达、带作用的使用关系、多来源共同目标。
3. 反事实消融：移去一个来源，观察条件指纹和 fixture 续写是否改变。原对局不被改写。
4. 新建分支继续、暂停、导出及删除。

公开正文和工程诊断是不同投影。模型获得的角色视图不含“哪个计算位置创造了我”等技术来源信息；读者正文也不显示内部操作地址。

## 自定义实验

网页左侧“创建实验”区域提供 **“＋ 自定义实验”**。选中已有预设后，可用 **“复制编辑”** 创建副本；自定义预设还会出现 **“编辑当前预设”**。内置预设只允许复制，不允许覆盖。

1. 填写预设标识、名称与说明。标识使用小写英文字母、数字、下划线或短横线，以字母开头；新建和复制须使用尚未存在的标识。
2. 配置 **3–8 个叙述位置**，分别填写 ID、显示名和私人背景 Markdown。每份背景最多 12000 个字符，可写过往生活、关系、初始看法与愿望；角色 ID 使用小写字母、数字、下划线，以字母开头。系统已有共有叙事纪律，背景作为初始材料，不是永恒身份指令。
3. 配置 **1–6 份共同表达**：填写安全标识、正文和开放作用标签。每份正文最多 6000 个字符，作用最多 80 个字符；表达 ID 不能使用 `seed-` 或 `expr-` 保留前缀。当前每份共同表达初始化时由全部所选位置承接，网页尚不提供任意连接拓扑编辑。
4. 点击 **“保存预设”**。保存只写文件，不调用模型，也不启动实验。随后选择预算与 provider，点击 **“创建实验”**，再单步或开始生成。

“创建实验”按钮旁会显示不可用的具体原因。选择 DeepSeek 时，须先在本机 `.env.local` 的 `OPENTALE_API_KEY` 字段填写密钥并保存，再点击“刷新模型配置”。诊断显示后端实际加载的文件路径，以及是否有空环境变量覆盖文件；不显示密钥内容。若标准字段没有识别到，请核对路径、字段名和保存状态；若 `OPENTALE_API_KEY` 被空环境变量覆盖，请从启动服务的环境中移除该覆盖后重新启动。离线夹具无需密钥。创建失败的原因保留在创建区域；成功后自动定位到“单步 / 开始运行”的控制区。

人物的私人信息保存在 Markdown；JSON 仅保存人物 `id`、`name` 等这里需要的系统元信息，不用目标字段代替私人背景。编辑已有预设会保存新版本，只影响之后创建的实验；已创建存档保有自己的初始材料和运行状态。若另一处编辑已更新当前版本，保存返回冲突而不覆盖，请刷新后重新编辑；复制另存也可保留自己的草稿。

默认自定义文件位于 Git 忽略的本机目录：

```text
runtime/presets/<预设ID>/
  current.json                       # 当前版本指针
  versions/<版本UUID>/
    preset.json                      # 预设信息、角色元信息及共同表达
    characters/<角色ID>/
      character.json                 # 仅 id/name
      character.md                   # 私人初始背景
```

完整版本写完并校验后才切换 `current.json`；历史版本保留。新建目录权限为 `700`，文件为 `600`，这些文件是本地明文，并未加密。若设置 `OPENTALE_DATA_DIR`，自定义预设位于该目录的 `presets/` 子目录。内置样例仍在公开的 `presets/`，网页不会改写它们。

建议先用 fixture 检查文件、共享关系、回流和存档，再在 `.env.local` 配好模型后用小预算验证语义。fixture 会响应自定义共享表达及绑定，但仍是机械机制示例，不是对人物背景的真实理解。密钥始终只填服务端 `.env.local`，不要填人物、共同表达或预设说明。

```sh
uv run pytest
uv run ruff check backend tests scripts
cd frontend
npm test -- --run
npm run build
cd ..
uv run python scripts/verify_demo.py
uv run python scripts/check_secrets.py
```

HTTP 验收脚本另起随机本地端口和隔离临时存储，检查实际生命周期、自定义预设保存/冲突/执行及服务重启，不读取本仓库 `.env.local`，不会请求付费 API。密钥检查扫描公开源码与 Git 暂存区，发现私有路径时仅报告路径，不读取私有文件。它不是对所有潜在秘密的完整证明。

## 启用真实模型

**将密钥只填写到本机文件 `/Users/huchenzi/Ready4AI/Project_OpenTale/Opentale_Demo/.env.local`。不要填写到 Markdown 文档、网页、对话或 Git 中。** 仓库已准备忽略的空文件；公开的 `.env.example` 只列字段名和非敏感默认值。

用本地编辑器填写：

```dotenv
OPENTALE_API_KEY=<在本地编辑器填写>
OPENTALE_BASE_URL=https://api.deepseek.com
OPENTALE_MODEL=deepseek-flash
OPENTALE_TIMEOUT_SECONDS=90
OPENTALE_MAX_OUTPUT_TOKENS=1600
OPENTALE_PORT=8231
```

设置文件权限：

```sh
chmod 600 .env.local
```

不要用会进入命令历史的带明文密钥命令。配置修改后，在没有任务运行时点击网页的“重新加载配置”，再创建 `deepseek` 对局。网页只显示配置是否就绪、模型名称和安全参数；密钥及服务地址不发往浏览器。

先用很小的调用、输出 token 和窗口预算单步测试。重试和失败尝试仍可能计费，预算是准入及停止控制，不是服务商账单的严格保证。当前实现不需要公开 CoT，也不会保留或显示模型推理内容。开发验收默认始终使用 fixture；提供密钥不等同于允许无上限测试。
