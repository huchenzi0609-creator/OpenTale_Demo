# 反身生成实验：实际能力与验收

本实验为 OpenTale 增加可选的 `reflexive` 运行模式。经典模式 `classic` 继续作为默认和对照，既有存档不会自动转入新模式。反身模式使用 schema 3，保存内容、方法与实际选择，使生成器可以提出方法、采用方法，再引用已经生效的方法或选择。

这里的“反身”是可执行的工程关系：生成结果能够改变下一次模型调用实际收到的材料及其组织方式。它没有修改模型权重、神经注意力、KV cache 或远程模型的内部算法，也没有实现任意自修改程序。

## 内容、选择与方法

| 对象 | 实际表示 | 可继续操作的部分 |
|---|---|---|
| 内容 | 请求中可见的 `content` 接口及其材料 | 进入方法输入；形成后续正文的条件 |
| 方法 | 不可变的 `MethodRecord` | 引用内容、既有方法或既有选择；规定顺序、数量及自然语言组织指令 |
| 选择 | 运行时计算的 `ChoiceRecord` | 保存本次被提供/采用的接口、活跃方法、材料分组、确切材料快照和输入指纹 |
| 采用关系 | `scope_id -> method IDs` | 指定人物或阅读作用域实际采用哪些方法；可局部释放 |

选择记录是软件执行轨迹，不是模型关于心理过程的自述。方法可以解释自己的表达倾向，但这种文字也不等于程序证明其意义正确。公开正文与技术面板分别投影；技术记录不需要成为人物知道的生活事实。

选择对象还向生成器投影此前实际取用与分组、提供/采用数量。仍在本次接口中的引用转为整数编号，旧的不可见引用只标记缺失数量；不编造编号，不暴露来源作者或推理。这样方法可以针对已有的组织方式生成变化，而不只是再次读到一段材料摘录。

人物作用域为 `position:<人物ID>`，阅读作用域为 `reading:<阅读ID>`。不同作用域可以采用不同方法，相互抵牾的组织指令可以并列保留。方法创建者记录用于技术追踪，不向叙述者公布隐藏的技术来源。

跨作用域取用选择时只导出可见的世界材料快照；未共享的初始主体背景仍按人物作用域过滤，阅读自身的此前段落不会因为 choice 引用直接共享。采用前会在副本中验证每个目标作用域的方法闭包能够实际展开，防止在来源处合法、在目标处无法取得材料的方法安装后阻断后续生成。

## 有限操作字母表

初版的方法定义包含：

- `inputs`：从本次请求提供的有限可见接口中取用材料。输入允许指向既有方法或选择。
- `order`：`listed` 按定义顺序展开；`reverse` 反向展开。
- `limit`：限制展开后材料数量。
- `instruction`：有限长度的自然语言组织指令，进入采用该方法的实际生成输入。
- `revises`：生成一个新版本并保留前版本；在指定作用域采用新版本时替换其前版本。
- `adopt` / `release`：在指定人物或阅读作用域采用或释放方法。

方法对方法的引用由运行时展开，选择对材料的引用使用其保存时的确切快照。多个方法保留分别展开的材料组与组织指令；运行时对展开步数和材料数量设置边界。不执行模型返回的代码，不授予文件、网络、密钥或配置修改能力。

一次求值最多 256 步、64 项材料、120,000 个完整材料/组织指令字符，每个作用范围最多采用 16 个方法。共享不可变子图采用单次求值缓存，保持顺序及重复材料的语义。候选接口提供标有截断状态的有限预览；真正选入的材料不会被预览截断。方法消融比较材料、分组和指令，不把仅方法编号变化宣称为输入变化。

新方法只能引用本次请求已经存在的对象。同一响应内 `draft:0` 等别名仅用于采用该响应刚创建的方法，不能作为另一方法的输入。这使依赖可以跨版本增长，而不会在同批请求中生成无限递归。数据引用及版本边界由内核校验，模型使用请求所属的整数索引，由 provider 编译持久 ID。

操作容量是本机工程边界：单次最多创建 4 个方法、提出 16 个采用/释放操作；单方法 1–32 个输入，展开选择上限 1–32，指令最多 1200 字符。这些限制不要求模型用满，也不表示模型拥有无限反思深度。

每个作用域最多同时采用 16 个方法；一次展开最多 256 个求值步骤和 64 份材料。候选接口通常提供至多 96 项，已采用方法所必需的依赖可以超过这一数量，但总接口容量最多 256 项；必需依赖不会为了满足常规候选数量而被静默截断。每个窗口仍有原来的本机请求长度、服务商上下文和输出预算约束。

## 一个窗口实际怎样运行

1. 冻结同一基础 revision，为所有人物准备本次可见对象、作用域、活跃方法和实际输入。
2. 人物并行形成正文与承接提案，可以同时提出方法和采用关系；反身模式允许没有普通 `rebind` 操作的提案。经典模式继续执行原有共同承接约束。
3. 联合安装正文承接和人物提出的方法变更，捕获实际提案输入的选择证据。
4. 重新编译采用方法后的实际材料与指令，形成各人物续写，并保存实际续写输入的选择证据。
5. 为全部参与阅读冻结同版输入，阅读各自生成正文和可选的方法变更。一个阅读产生的方法不会改变同窗口另一条阅读已经冻结的输入。
6. 安装成功的阅读正文，联合应用本窗口阅读的方法反馈。反馈可以在人物作用域采用阅读生成的方法，进入后续生成。
7. 保存阶段恢复点、快照和独立可执行事件。下一窗口继续引用此前形成的方法及选择。

阅读的焦点、历史与正文仍按轨迹独立保存。首段保持指定起点；已生成文字不会被方法修订自动重写。单独“呈现当前世界”也可以提出方法反馈，但不重新运行人物窗口。

无需固定的“二阶 Agent”或“高阶 Agent”。当方法采用内容，它组织内容；当方法引用另一个方法或选择并改变其作用，它形成可执行的反身依赖。阶数不作为权限或调度字段，也没有独立的无限反思协程。

初版窗口依然覆盖所有预设人物，使用同版本并行微批次；人物数量和动态生成位置机制未改变。反身方法可以选择材料、调整组织及在现有作用域生效，尚不能增减人物、任意修改调度器或自动生成新的基本操作类别。

## 在网页中开始

建议为本实验使用独立服务配置，避免 schema 3 实验档进入经典后端的数据目录。默认主服务仍使用 `runtime/` 与 `frontend/dist/`；实验配置使用 `runtime/reflexive/server-process.json`、`runtime/reflexive/server.log`、`runtime/reflexive/data/` 和 `runtime/reflexive/frontend-dist/`。主服务可以继续在 8231 运行，实验服务使用显式指定的 8232：

```sh
.venv/bin/python scripts/dev.py build --profile reflexive
.venv/bin/python scripts/dev.py detach --profile reflexive --port 8232
.venv/bin/python scripts/dev.py status --profile reflexive
```

随后打开 `http://127.0.0.1:8232`。`detach` 独立于当前终端运行；停止实验服务使用 `.venv/bin/python scripts/dev.py stop --profile reflexive`。省略 `--profile` 的 stop/status 只管理默认主服务，实验命令只管理自己的进程记录；脚本检查 PID、启动令牌和配置身份，避免终止另一个配置或重用该 PID 的进程。

实验前端构建只写入其独立 bundle 目录，不覆盖主网页；实验 SQLite 与自定义预设位于独立 `data/` 目录。首次不会自动复制主服务的实验档或私人预设。密钥仍由后端读取仓库根目录的 `.env.local`，启动脚本不读取、打印或复制密钥；新增配置只指定运行目录和端口。切换 Git 分支之前应停止依赖该分支代码的实验服务，保留的数据仍留在实验目录内。

1. 选择一个预设，在“新实验模式”选择“反身实验 · 生成并采用方法”。默认选项为“经典模式 · 共同条件承接”。
2. 选择“离线夹具”可以免费观察机械执行；选择 DeepSeek 使用服务端已配置密钥和该实验预算。
3. 点击“创建实验”；创建仅保存初始状态。点击“单步”完成一个窗口，或点击“开始”持续运行至暂停或预算边界。
4. 打开“生成方法与实际选择”，查看方法、作用域采用、修订谱系、实际材料选择及输入指纹。“方法版本”和“实际选择历史”每页显示 10 条。正文阅读显示叙述，不混入技术轨迹。
5. 需要比较时为同一预设另建经典实验。实验模式保存在存档中，已有经典存档不会因为网页切换选择而改变。
6. 在“方法离线消融”选择“消融作用域”及“消融方法”，点击“执行方法离线消融”，查看移除该作用域的方法后，实际选择与输入组织是否改变。该操作使用 detached 副本，不回写原实验，也不调用模型；运行中或窗口恢复未完成时入口禁用。

在方法详情中，可按作用范围点击“停止采用”。这是显式修改采用关系，不删除方法版本或旧正文；暂停或技术错误时可使用，包括已有恢复点的情况。已经冻结的调用仍按原输入完成，此后重新编译的输入采用新关系。操作不调用模型，并保存可重放的 method_released 事件。模型以后仍可再次采用该方法。

本次部署在独立实验目录本地复制了原服务的自定义预设，包括小说预设；复制后的预设可独立编辑。主服务存档没有迁移。根目录 `.env.local` 仍由后端按原流程读取，前端没有密钥字段。

所有生成阶段共享原有调用、Token、并行和窗口预算，未为反身操作建立隐藏额外额度。方法生成附在既有提案/阅读调用中，初版没有另加高阶监督模型调用。模型是否因为新增材料增加 Token 消耗，需要结合实际用量观察。

## 离线复现

在仓库根目录执行：

```sh
.venv/bin/python scripts/verify_reflexive.py
```

也可以在已安装项目依赖的环境运行 `uv run python scripts/verify_reflexive.py`。

脚本借助 `verify_demo.Server` 清除测试子进程继承的 `OPENTALE_` 配置，指向空临时根目录及独立 SQLite 数据库，使用随机本机回环端口。它不打开仓库 `.env.local`，不读取用户运行存档，不回传服务日志，只创建 fixture 实验。退出时停止隔离进程并删除临时数据。

验收内容：

- 默认经典模式一窗口仍保留共同承接行为。
- 反身模式创建 schema 3，创建与第二阅读配置均不调用生成器。
- 同一世界连续完成四窗口与双阅读。
- 方法采用、方法引用方法、方法引用选择、不可变修订谱系存在。
- 提案、续写和阅读均保存实际输入与材料选择。
- 阅读生成的方法被人物作用域采用。
- 每窗口从独立事件证据重放与当前语义状态一致。
- 方法消融改变实际输入组织，原存档及用量保持不变。
- 存档分支继续不改原档；真实进程重启后完整恢复且重放摘要稳定。

本分支的隔离 HTTP 验收已实际通过上述流程，包括至少三层方法引用链，以及至少一项方法消融造成材料 ID 选择变化。经典生命周期也可另运行 `scripts/verify_demo.py`，用于检查新增模式之外的原有行为。

离线夹具按预设的确定性策略创建、修订和采用方法，用于证明执行链成立。它不是“高阶注意力自发涌现”的真实模型证据。指纹变化能证明输入结构改变，不能独自证明模型理解了方法，或方法具有叙事价值。

本次开发验收：后端 468 项、前端 63 项测试通过，Ruff 和生产构建通过；隔离真实 HTTP 验收验证四窗口双阅读、消融、重放、分支与进程重启。另用同一 Runner 的隔离内存 Store 完成二十窗口夹具检验；这是执行持续性检查，不是磁盘长档性能基准。开发未调用付费 API。实验服务另保留四窗口双阅读的离线示例供网页查看。

## 真实模型实验应怎样判断

至少分开观察三件事：

1. **能力存在**：方法引用能够验证，实际输入被编译改变，恢复和重放一致。
2. **模型使用能力**：真实模型自行选择提出或采用组织方式，而非每轮照抄格式例文；也允许没有方法变更的窗口。
3. **组织承担表达作用**：变更影响后续怎样讲述，多个位置的联系或读法发生可追踪改变；没有变成反复复述同一意象的机械技巧。

经典模式与反身模式的比较需尽量固定预设、模型和预算，并记录输出及实际方法轨迹。方法消融先证明机制，再结合生成前后文本作语义判断；本机消融接口不会额外调用真实模型。

这个版本没有预设主题、剧情目标、全局文学裁判或统一虚构史。它提供方法可以进入后续生成的条件，不能保证意图、价值、相干性或文学性已经涌现。若真实模型只产生听起来深刻的组织说明，实际选择与文本效果都没有改变，应记录为模型尚未有效使用该能力。
