# OpenTale v0.2 架构与执行逻辑

## 从思想到运行状态

系统保存 `S = (E, U, K)`，并额外保存执行状态和局部阅读状态：

当前是单进程调度、单本机 SQLite 存储。这里的去中心化指虚构归属与生成依赖没有唯一真相裁判，并非已经实现分布式计算或节点共识协议。

| 思想对象 | 运行表示 | 实际作用 |
|---|---|---|
| 表达 E | `Expression`，稳定内部 ID 与内容 | 多个位置引用同一表达；它不是复制进独立故事的装饰 |
| 使用关系 U | `Use(position_id, expression_id, role, bindings)` | 同一表达可在各处承担不同的自然语言作用，存在带来源的多种绑定 |
| 续延 K | `Continuation`，条件指纹、依赖、未完成种子、已形成表层 | 变化使相关续延的实际生成条件改变 |
| 转用 | `Proposal.operations` 中的 `rebind` | 改写某位置对已有共享表达的使用 |
| 阅读位置 | `reading`、`ReadingFrame`、故事段及重新理解指向 | 从联合变化后的内容形成线性展开，同时记录旧段的新用法 |

角色 MD 是初始化种子。它进入初始使用关系，而不是每次调用都重新强制注入的永恒身份说明。系统保留原种子用于来源和初始条件，但活跃生成依据当前使用关系。`主体背景` 用法被转用后，其当前绑定值替代原背景进入 frame。位置 ID 管理计算，不裁定虚构中的人物永远是谁；v0.2 的位置显示名仍固定，不包含自动改名机制。

`role` 是开放文本；系统不预设固定的记忆、梦、过去等语义全集。v0.2 的操作类别暂时只有 `rebind`，不包含动态生成位置、拆分、合并或删除表达。这是 demo 对运行范围的明确简化。

## 预设编辑与初始化边界

左侧“＋ 自定义实验”创建预设，内置预设可“复制编辑”，自定义预设可“编辑当前预设”。编辑器接受 3–8 个位置及其 ID、名称、私人背景 Markdown，每份 MD 最多 12000 字符；1–6 份共同表达各有 ID、正文（最多 6000 字符）与开放作用标签（最多 80 字符）。目前每份共同表达初始时共享给全部所选位置，尚没有自定义任意连接拓扑。

`PresetLibrary` 组合只读的源码 `presets/` 与 Git 忽略的 `runtime/presets/`。自定义预设按 `预设ID/versions/版本UUID/` 保存完整版本：`preset.json` 保存预设信息、共同表达和人物元信息；`characters/角色ID/character.json` 只保存 ID/name，`character.md` 保存私人背景。初始观点、关系和愿望都属于 MD，不是公开的规则目标字段。

保存先写出并校验全部文件，再原子替换 `预设ID/current.json`。编辑携带 `expected_version`；冲突或试图覆盖内置预设时返回安全 409，不覆盖当前版本。保存使用进程内锁和 `fcntl` 进程锁，文件描述符相对操作及 no-follow 检查拒绝不安全的链接路径。当前面向 macOS / Linux，尚不支持 Windows 文件系统接口。

新目录为 700、文件为 600，但内容是本地明文，未加密；历史版本保留。修改自定义预设只切换后续初始化的输入，创建好的 `Snapshot` 已持有自己的种子、表达、使用和事件，编辑不会回写已有存档。保存、新建实验本身不调用模型；只有后续开始或单步进入生成。模型类型和密钥仍由服务端 `.env.local` 管理，不属于预设人物资料。

## 一个窗口的完整执行

1. **起窗**：冻结基础 revision，建立 `pending`；活跃位置取得同一版本的条件。v0.2 每窗口覆盖预设中的全部 3–8 个位置，尚没有按依赖激活部分位置的动态群组调度。
2. **提案**：模型形成第三人称的未完成正文片段及其承接目标。provider 将每个目标机械编译为 `rebind`，以片段原文同时生成 `value` 和精确 `anchor`，避免要求模型重复抄写同一段文字；仍兼容已经合法的旧操作格式。目标必须是已有同伴位置及可用表达，提案必须改变其他位置的活跃条件。
3. **联合安装**：校验全部提案版本，按确定顺序归一化操作集合，原子安装整批变化。两个来源对同一目标的绑定并列保留；不会按最快响应或最后写入挑选公共真相。
4. **实际续延**：重新编译各位置条件，更新指纹和依赖，在新条件下生成表层内容。它不是把变化追加在旧角色档案后继续原样生成。
5. **呈现**：呈现器取得更新后的候选、当前作用、此前故事段和开放关系，生成一段线性阅读与焦点选择。`reinterprets` 可以指向已有故事段，表达“旧段现在如何被使用”而非偷偷改写过去字句。
6. **保存**：保存版本化快照、可执行语义事件与阶段诊断，记录用量、窗口和当前阶段；下一窗口从保存状态继续。

网络调用位于 provider，预算及阶段状态位于 runner，内核只处理确定性的领域变更。存储不充当故事真相裁判；工程 revision 是过时计算检测工具。

## 嵌合度的实际落实与不足

正文种子与操作同一次产生，精确 anchor 阻止纯粹无关的外部操作地址。操作必须改变其他活跃条件，生成器必须使用安装后的视图。呈现同样取得关系状态，而非只拼接人物输出。

这些约束证明的是结构和正文之间有可执行的连接。它们不能证明 anchor 在语义上充分支持操作，也不能证明模型真的理解了转用或正文具有文学意义。当前是“结构化生成 + 语义边界重入”，尚非模型内部原生表达程序。

一次续延挂起保存的是正文、依赖和程序阶段；恢复时重新构造上下文并调用模型。它没有保存远程模型的神经隐状态，没有合并 KV cache，也没有跨模型注意力。

## 冲突、来源与演员视图

v0.2 的呈现输入过滤未共享的原始人物背景，只保留已形成的表层叙述及当前共享表达的用法。人物可以在叙述中显露私人材料；呈现者不能直接浏览全部人物档案来制造全知叙述。

技术绑定来源用于诊断、消融和可恢复执行。演员视图只包含当前表达、作用和值，不获得技术 `source_position_id`、原始提案追踪或幕后创建者信息。初始知识和当前条件是叙事输入，不告诉人物“你由另一个模型创造”。

`peer_interfaces` 提供其他位置可承接用法的目标句柄：位置 ID、表达 ID 和作用标签。它不含对方背景内容或绑定来源，允许模型明确指向对方的主体背景用法，而不是猜测内部地址。模型是否选择并有效使用这种接口，仍需真实实验。

相同表达在不同位置的作用可以冲突，同一目标中的多来源值可以并存。v0.2 不自动消解它们为唯一世界版本，也不保证模型会在自然语言中保持全部冲突。

`fork` 复制当前运行状态形成独立实验分支；没有自动合并或公共历史共识。分支与创建来源字段是工程信息，不会自动成为人物知道的剧情。

## 恢复与资源控制

阶段性结果在 `pending` 保存。提案部分成功后失败，下一次 step 使用已经成功的部分；整批已安装后失败，不重复安装同一批，继续未完成的续延或呈现。持久化阶段信息可用于进程重启后的继续。

进程恢复依据完整快照。独立的语义重放器从 `created` 中的初始状态开始，重新执行 `batch_installed` 的完整类型化提案，采用 `continuation_resumed` 保存的表层结果，安装 `presented` 中的呈现程序，逐字段核对位置、表达、使用关系、续延、正文与读法。

`GET /api/runs/{id}/replay` 从数据库独立事件表读取证据；不调用任何 provider、不修改原档。缺失、损坏或过时证据返回安全的检查失败，不以快照自带事件替代受损证据。它不重演 API 计费、真实墙钟或全部 pending/调度控制状态；阶段恢复和这些运行状态仍由快照负责。

预算控制调用次数、Token、并行和窗口。新实验默认总 Token 预算为 128000，最多可保存 512000（十进制 512K）；调用与窗口最多各 1000，并行最多 8。`GET /api/config` 与重新加载配置响应提供 `budget_bounds`，前台依据服务端边界校验输入。提高程序上限不会自动改变已保存实验的额度，也不会触发生成。

加载存档后，预算输入框显示该实验已保存的 `Limits`。稳定状态下点击“更新本实验预算”，通过 `PATCH /api/runs/{id}/limits` 保存完整预算并返回当前快照。运行中的任务须先暂停；新调用预算不得小于已用调用数，窗口预算不得小于已完成窗口数，Token 预算不得小于输入、输出、未知及预留 Token 的总占用。更新保留人物、正文、`pending`、阶段、revision 和已计用量，不调用 provider、不重跑任何阶段。预算耗尽的存档更新后转为 `paused`，清除预算耗尽错误，之后由单步或开始继续；其他模型错误仍保留供定位。预算更新事件记为 `limits_updated`，不构成叙事变更。

runner 在发出请求前做准入并记录调用；失败调用也计入次数。输出校验失败若带有合法服务商用量，仍按实际输入、输出 Token 结算；无法获知用量的失败保留保守未知占用。实验预算是本机准入条件，不是服务商账单的绝对上限。

本机接受边界统一定义在 `backend/opentale/capacity.py`，各步骤按不同单位校验：

| 对象 | 本机接受上限 | 单位与范围 |
|---|---|---|
| 提案片段 | 128 | 每次提案；单片段最多 256 个目标 |
| 承接操作 | 256 | 单次提案所有片段目标编译后的总数 |
| 提案正文 | 32000 | 所有片段拼接后的字符数，包含换行 |
| 承接片段、操作值和锚点 | 16000 | 含承接目标的单片段及单操作字符数 |
| 活跃绑定值及锚点 | 32000 | 持久化领域数据的单字段字符数 |
| 续延正文 | 32000 | 每次续延返回的字符数 |
| 呈现正文 | 64000 | 每次呈现返回的字符数 |
| 模型请求 | 512000 | 系统指令、schema 与序列化输入合计字符数 |
| 模型响应正文 | 256000 | 响应 envelope 内 content 的字符数 |
| 模型响应传输 | 2 MiB | 整份响应字节数，防止无界分配 |
| 单次模型输出配置 | 32768 | `OPENTALE_MAX_OUTPUT_TOKENS` 可配置的本机 Token 上限 |

这些上限允许较丰富的输出，不要求模型用满。总预算、单次输出、字符容量和传输字节各自独立；放宽本机边界不会扩大远程模型实际支持的上下文或输出。来源引用、有效目标、版本、JSON 与私有信息检查仍执行，不因扩容而截断操作或偷偷改写正文。

暂停在安全操作边界生效。它不承诺取消已经发给服务商的请求，也不把一半完成的联合安装暴露为有效状态。公开错误只有安全 code、message、retryable；恢复保留已经完成的故事与阶段结果。

## 呈现策略

呈现器作为当前阅读位置操作候选关系，而不是永久的全知总结者。它选择焦点、相关表达和可被重新承接的已有故事段，形成一段正文。前台提供正文阅读、各位置的活跃条件和工程证据三个视图。

这种设计让关系参与呈现，但 v0.2 仍然使用一次独立的 `present` 调用。它不是已经实现所有序列化策略的通用语言，也不能保证有限上下文中所有相关表达都被正确承接。

离线 fixture 根据 `peer_interfaces` 选择至少另外两处持有相同表达 ID 与作用的共同接口，稳定选择覆盖更多位置的接口，排除仅属自身的背景。它不把自定义表达 ID 固定成 `e-letter`；没有书信或门的实际内容时使用通用机械动作。续延读取选中用法的全部活跃绑定，呈现使用候选之间共享的表达、开放关系、当前焦点和已访问位置。上述响应用于检验执行链，不能视作对私人故事的理解或文学性能。

## 目录责任

- `backend/opentale/domain.py`：领域模型与版本。
- `capacity.py`：共享的步骤容量、模型传输与预算边界。
- `kernel.py`：条件编译、提案验证、联合更新与结构审计。
- `presets.py`：受约束的网页预设定义、版本化私有文件库与快照初始化。
- `runner.py`：预算、并发、阶段恢复与呈现。
- `storage.py`：私有快照、事件、恢复、分支、导出及删除。
- `replay.py`：重新执行语义事件并核对 E/U/K、正文及读法。
- `providers/`、`config.py`：离线或远程生成、安全配置与有限失败。
- `api.py`：HTTP 状态边界、任务控制、静态网页与公开投影。
- `frontend/`：控制、正文阅读、关系与诊断；不持有 API key。
- `scripts/`：启动、隔离 HTTP 验收和公开源密钥检查。

当前验证关注真实引用、联合安装、条件改变和可恢复运行。语义回流、长期相干与文学效果需另行授权小预算实验。
