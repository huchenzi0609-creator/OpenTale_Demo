# OpenTale v0.1 架构与执行逻辑

## 从思想到运行状态

系统保存 `S = (E, U, K)`，并额外保存执行状态和局部阅读状态：

当前是单进程调度、单本机 SQLite 存储。这里的去中心化指虚构归属与生成依赖没有唯一真相裁判，并非已经实现分布式计算或节点共识协议。

| 思想对象 | 运行表示 | 实际作用 |
|---|---|---|
| 表达 E | `Expression`，稳定内部 ID 与内容 | 多个位置引用同一表达；它不是复制进独立故事的装饰 |
| 使用关系 U | `Use(position_id, expression_id, role, bindings)` | 同一表达可在各处承担不同的自然语言作用，存在带来源的多种绑定 |
| 续延 K | `Continuation`，条件指纹、依赖、未完成种子、已形成表层 | 变化使相关续延的实际生成条件改变 |
| 转用 | `Proposal.operations` 中的 `rebind` | 改写某位置对已有共享表达的使用 |
| 阅读位置 | `reading`、`ReadingFrame`、故事段及重新理解指向 | 从联合变化后的内容形成线性展开，同时记录旧段的新用法 |

角色 MD 是初始化种子。它进入初始使用关系，而不是每次调用都重新强制注入的永恒身份说明。系统保留原种子用于来源和初始条件，但活跃生成依据当前使用关系。`主体背景` 用法被转用后，其当前绑定值替代原背景进入 frame。位置 ID 管理计算，不裁定虚构中的人物永远是谁；v0.1 的位置显示名仍固定，不包含自动改名机制。

`role` 是开放文本；系统不预设固定的记忆、梦、过去等语义全集。v0.1 的操作类别暂时只有 `rebind`，不包含动态生成位置、拆分、合并或删除表达。这是 demo 对运行范围的明确简化。

## 一个窗口的完整执行

1. **起窗**：冻结基础 revision，建立 `pending`；活跃位置取得同一版本的条件。v0.1 每窗口覆盖预设中的全部三个位置，尚没有按依赖激活部分位置的动态群组调度。
2. **提案**：模型形成第三人称的未完成正文种子与转用操作。每个操作的 `anchor` 必须是提案正文中的准确子串，目标必须是已有位置及共享表达，提案必须改变其他位置的活跃条件。
3. **联合安装**：校验全部提案版本，按确定顺序归一化操作集合，原子安装整批变化。两个来源对同一目标的绑定并列保留；不会按最快响应或最后写入挑选公共真相。
4. **实际续延**：重新编译各位置条件，更新指纹和依赖，在新条件下生成表层内容。它不是把变化追加在旧角色档案后继续原样生成。
5. **呈现**：呈现器取得更新后的候选、当前作用、此前故事段和开放关系，生成一段线性阅读与焦点选择。`reinterprets` 可以指向已有故事段，表达“旧段现在如何被使用”而非偷偷改写过去字句。
6. **保存**：保存版本化快照、可执行语义事件与阶段诊断，记录用量、窗口和当前阶段；下一窗口从保存状态继续。

网络调用位于 provider，预算及阶段状态位于 runner，内核只处理确定性的领域变更。存储不充当故事真相裁判；工程 revision 是过时计算检测工具。

## 嵌合度的实际落实与不足

正文种子与操作同一次产生，精确 anchor 阻止纯粹无关的外部操作地址。操作必须改变其他活跃条件，生成器必须使用安装后的视图。呈现同样取得关系状态，而非只拼接人物输出。

这些约束证明的是结构和正文之间有可执行的连接。它们不能证明 anchor 在语义上充分支持操作，也不能证明模型真的理解了转用或正文具有文学意义。当前是“结构化生成 + 语义边界重入”，尚非模型内部原生表达程序。

一次续延挂起保存的是正文、依赖和程序阶段；恢复时重新构造上下文并调用模型。它没有保存远程模型的神经隐状态，没有合并 KV cache，也没有跨模型注意力。

## 冲突、来源与演员视图

技术绑定来源用于诊断、消融和可恢复执行。演员视图只包含当前表达、作用和值，不获得技术 `source_position_id`、原始提案追踪或幕后创建者信息。初始知识和当前条件是叙事输入，不告诉人物“你由另一个模型创造”。

`peer_interfaces` 提供其他位置可承接用法的目标句柄：位置 ID、表达 ID 和作用标签。它不含对方背景内容或绑定来源，允许模型明确指向对方的主体背景用法，而不是猜测内部地址。模型是否选择并有效使用这种接口，仍需真实实验。

相同表达在不同位置的作用可以冲突，同一目标中的多来源值可以并存。v0.1 不自动消解它们为唯一世界版本，也不保证模型会在自然语言中保持全部冲突。

`fork` 复制当前运行状态形成独立实验分支；没有自动合并或公共历史共识。分支与创建来源字段是工程信息，不会自动成为人物知道的剧情。

## 恢复与资源控制

阶段性结果在 `pending` 保存。提案部分成功后失败，下一次 step 使用已经成功的部分；整批已安装后失败，不重复安装同一批，继续未完成的续延或呈现。持久化阶段信息可用于进程重启后的继续。

进程恢复依据完整快照。独立的语义重放器从 `created` 中的初始状态开始，重新执行 `batch_installed` 的完整类型化提案，采用 `continuation_resumed` 保存的表层结果，安装 `presented` 中的呈现程序，逐字段核对位置、表达、使用关系、续延、正文与读法。

`GET /api/runs/{id}/replay` 从数据库独立事件表读取证据；不调用任何 provider、不修改原档。缺失、损坏或过时证据返回安全的检查失败，不以快照自带事件替代受损证据。它不重演 API 计费、真实墙钟或全部 pending/调度控制状态；阶段恢复和这些运行状态仍由快照负责。

预算控制调用次数、token、并行和窗口。runner 在发出请求前做准入并记录调用；失败调用也计入次数。失败时服务商没有返回的 token 用量可能未知，因此不是绝对账单上限。

暂停在安全操作边界生效。它不承诺取消已经发给服务商的请求，也不把一半完成的联合安装暴露为有效状态。公开错误只有安全 code、message、retryable；恢复保留已经完成的故事与阶段结果。

## 呈现策略

呈现器作为当前阅读位置操作候选关系，而不是永久的全知总结者。它选择焦点、相关表达和可被重新承接的已有故事段，形成一段正文。前台提供正文阅读、各位置的活跃条件和工程证据三个视图。

这种设计让关系参与呈现，但 v0.1 仍然使用一次独立的 `present` 调用。它不是已经实现所有序列化策略的通用语言，也不能保证有限上下文中所有相关表达都被正确承接。

## 目录责任

- `backend/opentale/domain.py`：领域模型与版本。
- `kernel.py`：条件编译、提案验证、联合更新与结构审计。
- `runner.py`：预算、并发、阶段恢复与呈现。
- `storage.py`：私有快照、事件、恢复、分支、导出及删除。
- `replay.py`：重新执行语义事件并核对 E/U/K、正文及读法。
- `providers/`、`config.py`：离线或远程生成、安全配置与有限失败。
- `api.py`：HTTP 状态边界、任务控制、静态网页与公开投影。
- `frontend/`：控制、正文阅读、关系与诊断；不持有 API key。
- `scripts/`：启动、隔离 HTTP 验收和公开源密钥检查。

当前验证关注真实引用、联合安装、条件改变和可恢复运行。语义回流、长期相干与文学效果需另行授权小预算实验。
