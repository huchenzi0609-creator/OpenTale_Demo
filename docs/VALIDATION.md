# 验收范围与证据

## 三种不同的结论

1. **运行机制成立**：领域、阶段和存储测试可以证明版本校验、联合安装、恢复、预算及安全边界。
2. **fixture 对机制有可观察响应**：离线生成器读取活跃条件，消融确实改变其输出；它证明运行链条使用了条件，而非真实模型具有同样效果。
3. **真实模型能够有效承接**：需要用户授权的有预算实验。格式正确、条件指纹改变或调用成功都不能单独证明相干与文学性。

v0.2 的自动验收覆盖前两项，不冒充第三项。

## 机制验收矩阵

| 要求 | 需要观察的证据 | 不足以证明它的现象 |
|---|---|---|
| 多方共同进入 | 同一基础版本的整批操作安装；顺序变化不改变内核结果 | 多人物各说一段、随后拼接 |
| 同一个活跃目标接受两个来源 | 目标使用关系保留两来源，联合目标审计显示参与者 | 只共同出现一个名字 |
| scoped 归属 | 不同位置保留不同作用和值，同一目标保留冲突绑定 | 归一化成唯一人物历史 |
| 真实引用 | 多个使用引用同一 expression ID，重绑定改变实际 frame | 在各自 prompt 复制一个共同道具 |
| 转用与表达连接 | anchor 属于提案正文，操作改变 peer 活跃条件 | 任意 JSON 旁注或自我追加 |
| 过时计算安全 | stale proposal 被拒，活跃 frame 使用新 revision | 老提案覆盖新状态 |
| 实际条件变化 | 指纹、使用值和续延依赖有变化；演员视图采用新绑定 | 只添加事件记录 |
| 语义消融的离线响应 | detached copy 移除来源后 fixture 正文改变，原档不变 | 指纹变化但输出与输入无关 |
| 暂停及恢复 | 成功阶段被保存，失败后只补做未完成部分 | 全窗口重跑导致重复安装/计费 |
| 重启保存 | 实际服务退出再启动，HTTP 取回同一快照 | 只在内存对象上 round-trip |
| 可执行语义事件 | 从独立事件表重算 E/U/K、正文和读法；删改证据时检查失败 | 仅比较导出的 JSON；不代表重演外部计费或全部控制状态 |
| 调用前准入 | 预算不足时不超过允许调用数 | 请求发出后才检查预算 |
| 预算扩容与恢复 | 5120000 Token 可保存、5120001 被拒；稳定时更新保留用量和恢复点，原档可继续 | 仅增大网页数字却没有修改存档预算 |
| 步骤容量一致 | 共享常量同时约束领域、provider schema、提示词与配置；大于旧限额的合法输出可接受 | 任意截断多余操作后宣称成功 |
| 私有信息边界 | 演员 frame 无技术来源；公开 config/export 无密钥、raw response、CoT | UI 仅隐藏字段但 API 仍返回 |
| 多入口序列化 | 同一世界的两条呈现协程实际重叠，首段从指定位置展开，分别持有有效共享表达与自己的历史 | 两个标签展示同一段正文，或独立重跑人物世界 |
| 阅读部分恢复 | 一条失败后另一条已安装的正文、调用及事件保留，恢复只补失败者 | 失败时清空成功段落并重复计费 |
| 当前世界单独呈现 | 只新增当前 revision 的一条阅读，人物、用法与窗口数不变；同轨迹同版本再次请求不计调用 | 用新窗口或 fork 冒充另起阅读 |
| 阅读历史隔离及迁移 | 跨轨迹 reinterprets 被拒且无状态变化；v1 全部正文与读法迁入 main，重放一致 | 旧档加载成功但丢失以前的正文 |
| 分支与删除 | 分支继续不改变原档；删除非活跃档的快照及事件记录 | 列表仅隐藏已删档；不代表磁盘安全擦除 |
| 自定义资料落盘 | MD 与 ID/name 元信息分别持久化，完整版本校验后发布 | 编辑器只在内存保留草稿 |
| 预设编辑安全 | 内置只读、重复 ID/过时版本冲突；已有存档不变 | 修改当前预设时回写正在运行的对局 |
| 任意共享载体 | 自定义表达 ID/开放作用在多个窗口、重放与消融中生效 | 所有场景仍只能使用固定 `e-letter` |
| 网页入口可操作 | 新建、复制、修改、字段上限、保存错误保留草稿与刷新选择测试 | 只有后端接口而无可见入口 |

模块测试分别在 `tests/` 和 `frontend/`。`GET /api/verify` 在隔离内存/存储中执行实际内核验收；网页可以查看每条检查，而非仅显示预制“通过”标语。

## 真实 HTTP 离线验收

```sh
uv run python scripts/verify_demo.py
```

脚本使用独立临时配置和随机回环端口启动真实服务，保留原有健康/安全配置、内置机制验收、创建/单步、联合审计、反事实与原档不变、语义事件重放、分支独立、退出与重启持久化、重放摘要稳定、导出、预算耗尽、后台控制、删除及清空列表检查。

预算验收通过真实 HTTP 核对公开 `budget_bounds`，创建并运行 5120000 Token 实验，拒绝 5120001 Token，确认默认预算为 128000。严格预算耗尽后，`PATCH /api/runs/{id}/limits` 只保存额度，保留既有用量、revision 和恢复点；原档继续完成窗口，并核对预算更新后的语义事件重放。已用调用数以下的降额被拒且快照不变。阶段恢复、未知 Token 占用、普通模型错误保留与运行中拒绝更新还由隔离单元测试验证。

多阅读流程通过真实 HTTP 新建第二入口（配置保存不调用模型）、运行共享窗口、核对两条轨迹的首段与不同段落 ID、关闭自动跟随、单独呈现当前世界与同版幂等、重新启用后继续，以及重启与全轨迹语义重放。单元测试另外用协程屏障验证呈现确实并行，并让一个呈现器失败后核对成功结果与已用调用保留、只重试缺失轨迹；无付费调用。

新增流程实际通过 HTTP 新建自定义预设、从目录读取完整资料、编辑发布新版本，并检查重复 ID、过时版本与内置覆盖冲突。自定义 fixture 实验使用任意共享表达 ID/作用连续完成两窗口，检查共同输入、反事实、语义重放、分支、编辑不改原档和服务重启后的预设/存档持久化。脚本只检查自己写出的临时 MD/JSON 和 700/600 权限，不读取用户材料；保存测试不会调用模型。权限是本机访问限制，不是加密。

它仅创建 fixture 对局，清除子进程继承的 `OPENTALE_` 配置变量并指向空临时根目录。不会打开仓库 `.env.local`，不会读取模型密钥，服务标准输出不回传。脚本退出时停止测试服务并删除临时数据，不修改用户存档。

预设文件库使用 POSIX no-follow 文件操作与 `fcntl` 锁，当前验证平台为 macOS / Linux。预设单元测试覆盖长资料边界、独立文件库实例的并发编辑冲突、损坏资料、符号链接拒绝与发布失败；fixture 测试覆盖 3–8 个位置的连续三窗口及批次顺序独立。这些证据不推导 Windows 支持或真实模型语义正确。

## 以后如何做小预算模型验证

不要以“文学性高”作为运行机制的代用指标。第一批实验可以只观察：

- 改变一个来源的归属/作用，目标人物是否调整实际叙述，而非机械复述操作。
- 两来源共同构成时，目标是否真正同时承接，是否漏掉一方或自动归一化。
- 初始角色身份被重绑定后，是否仍被反复注入的旧档案覆盖。
- 正文是否泄漏内部引用、创建者追踪、调试 ID 或幕后强制构想。
- 呈现是否使先前内容取得新用法，还是仅总结所有动作。
- 同预算不同策略是否影响相干；记录调用数、有效 token、延迟和失败阶段。

对比应在分支或 detached 副本中进行，不偷偷修改原档。结构审计可以定位机制；模型语义判读仍需要人类或另行定义的评价方法。不要为了得到“通过”增加一个自动统一虚构历史的裁判。
