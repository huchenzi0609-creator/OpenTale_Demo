# 反身生成 v2：使用方式、执行机制与验证边界

本说明对应显式选择的 `reflexive_v2` 引擎和 schema 5。它把可执行方法、嵌套视图、局部回应及输入证据接入现有共同生成流程。经典模式仍为新建实验的默认选项，旧 `reflexive` 模式继续使用原有方法解释器。既有存档不会因网页切换选项而改变模式。

本版实现的是一个可验证的反馈通路：方法改变材料组织，组织进入生成输入，生成者可以对已经可见的组织提出局部回应，回应又可以被后续方法读取。离线夹具证明这条通路能够执行和保存。真实模型是否因此形成持续的叙事意图，需要另做文本观察和受控实验。

## 从网页开始

1. 在“新实验模式”选择“反身实验 v2 · 视图、方法与回应”。
2. 选择初始叙事。“离线夹具”不调用模型 API；DeepSeek 使用后端已有配置。
3. 点击“创建实验”。创建仅保存初始状态。点击“单步”执行一个窗口，或点击“开始运行”持续推进。
4. 在“连续阅读”看正文，使用“新建阅读”建立独立起始位置和阅读历史。
5. 打开“生成方法与实际选择”，查看方法定义、修订谱系、采用位置、实际组织和局部回应。
6. 在“检索与读取完整材料”选择读取位置，输入关键词或留空浏览。点击“读取完整对象”取回当前存档中该位置可见的完整材料。

检索、读取完整对象、离线消融和创建配对实验都不调用模型。只有生成步骤消耗实验调用预算；选择付费模型后，生成步骤会使用 API。

方法和选择历史分页显示。视图保持层级分组与关系，方法程序可以展开检查。局部回应标注其可见范围；执行后果单独显示，二者不会混入“连续阅读”的正文。

“验证与诊断”提供请求证据和依赖调度观察。请求证据显示阶段、作用域、版本、输入摘要、逐次尝试和用量。保存的输入帧与请求投影不会在通用事件详情中直接展开。可读的选材快照位于反身技术面板。

### 隔离运行配置

在仓库根目录执行：

```sh
.venv/bin/python scripts/dev.py build --profile reflexive
.venv/bin/python scripts/dev.py detach --profile reflexive --port 8232
.venv/bin/python scripts/dev.py status --profile reflexive
```

随后打开 `http://127.0.0.1:8232`。若这个配置已经运行，先在网页暂停实验，再执行 `stop --profile reflexive`，重新构建和启动。`detach` 启动的服务独立于终端运行。

| 配置 | 默认主服务 | `--profile reflexive` |
|---|---|---|
| 常用端口 | 8231 | 显式指定 8232 |
| 数据目录 | `runtime/` | `runtime/reflexive/data/` |
| 前端构建 | `frontend/dist/` | `runtime/reflexive/frontend-dist/` |
| 进程记录 | `runtime/server-process.json` | `runtime/reflexive/server-process.json` |

隔离配置不会自动迁移主服务的存档或自定义预设。停止实验配置使用：

```sh
.venv/bin/python scripts/dev.py stop --profile reflexive
```

该配置隔离进程记录、数据库和构建产物，两个服务仍使用当前检出的后端源码。切换分支或更新源码时，应分别管理依赖该检出的服务。默认配置的 `stop` 不会替代实验配置的 `stop`。

密钥仍由后端读取仓库根目录 `.env.local` 的 `OPENTALE_API_KEY`；网页没有密钥输入字段。验证脚本不加载此文件。不要将密钥填进预设、人物资料、方法指令或阅读名称。

## 主要对象

| 对象 | 保存内容 | 当前作用 |
|---|---|---|
| `MethodRecord` | 不可变定义、语言版本、修订前版本、创建位置 | 在指定作用域编译生成输入；可被检查和改版 |
| `View` / `ViewRecord` | 层级分组、关系、材料 ID、冻结材料与依赖 | 保留组织并进入后续生成；可被再次读取 |
| `ChoiceRecord` | 提供对象、实际选材、采用方法、编译输入及计划摘要 | 说明某次调用的组织实际如何形成 |
| `ResponseRecord` | 局部解释、回应对象、依据、可见范围 | 成为后续可检索和读取的文本材料 |
| `EffectRecord` | 同位置同阶段的前后输入摘要、选材增减、回应依赖 | 提供执行诊断；不裁定叙事价值 |
| `ObjectVersion` | 对象完整值与内容版本、私人作用域 | 解析固定版本引用，避免把旧值悄悄替换为新值 |
| `RequestEnvelope` | 冻结输入、阶段及策略版本、请求投影摘要、逐次尝试 | 支持恢复、计费核查及输入证据验证 |

作用域采用关系独立于方法创建者。人物作用域写作 `position:<id>`，阅读作用域写作 `reading:<id>`。一个方法可以在多个有权限的位置被采用；停止一个位置的采用，不会删除定义或其他位置的采用。

`EffectRecord.response_ids` 表示本次实际依赖了哪些回应。它不是“已经有谁对这个后果发表评论”的名单。执行后果作为 `effect` 对象进入作用域内的目录，支持 `query.kinds=["effect"]`、`read`，并可成为局部回应的 `about/evidence`。对象提供实际输入是否改变、前后选择、采用方法以及新增/移出的材料引用；正文摘要仅陈述变化与数量，不把变化自动解释为叙事进步。权限同时继承前后两次完整选择及其依赖：即使当前材料公开，旧选择含私有材料或私有组织时，整个后果对象仍对其他位置隐藏。旧记录若缺少前一次选择的确切关联，则保守隐藏，避免通过“移出的材料”泄露私有信息。

## 可执行程序的操作字母表

v2 方法包含 `language_version: 2` 和 `program`。程序按顺序求值，步骤 ID 在程序内唯一；一个步骤只能使用此前类型相符的步骤结果。最终 `output` 必须指向视图。

| 操作 | 输入 | 结果与含义 |
|---|---|---|
| `read` | 对象引用列表 | 读取完整对象或指定文本范围，形成视图 |
| `query` | 关键词、可选类型与关联对象、可选数量 | 在当前有权限的完整对象目录中检索，再读取结果形成视图 |
| `group` | 此前的视图步骤、分组标签 | 保留子视图，建立新的层级组织 |
| `relate` | 此前的视图步骤、带标签的有向关系 | 建立输入视图之间的关系，保留各自内部结构 |
| `inspect` | 一个方法对象引用 | 取得方法定义，尚不执行其内容 |
| `revise` | 已检查或已改版的方法、补丁 | 生成新的方法定义，保留修订关系 |
| `apply` | 已检查或已改版的方法步骤 | 执行该定义，取得视图 |

`apply` 当前执行方法自身声明的读取与查询，并没有额外的任意参数绑定接口。程序也没有 `generate` 操作：执行器不直接调用子模型、文件系统或网络，不执行返回的 Python/JavaScript。模型提出程序的时机仍是人物构想和阅读呈现。

下面是一个结构示意。占位符必须换成本次可见的真实方法引用，不能直接提交：

```json
{
  "language_version": 2,
  "steps": [
    {"id": "prior", "op": "inspect", "ref": {"object_id": "<visible-method-id>", "mode": "live"}},
    {"id": "changed", "op": "revise", "input": "prior", "patch": {"instruction": "<new-organization-instruction>"}},
    {"id": "result", "op": "apply", "method": "changed"}
  ],
  "output": "result"
}
```

改版结果在安装新提案时经过编译验证，作为新定义留存。执行该定义与将其单独采用是两个操作；现有版本不会被原地覆盖。补丁省略字段表示保留原值，显式 `limit: null` 表示取消该选材限制。

`ObjectRef` 有两种引用方式：`live` 在编译时解析当前可见值；`version` 必须提供确切版本。实际依赖记录保存解析后的固定版本。可选 `start` / `end` 使用 Python 字符串切片的字符偏移，起点包含、终点不包含；它们不是字节或段落编号。结构化视图须整体读取，不支持按文本范围裁切后冒充完整视图。

方法的嵌套应用使用迭代求值，检测当前调用路径上的循环。系统没有固定“注意力阶数”字段；跨窗口可以继续检查和改版已有方法。无意义的单输入空标签包装不会仅因多一层执行 ID 就改变编译输入摘要。

v2 可以执行原有 `language_version: 1` 方法，适配器保留其串接、反转和数量选择含义。旧 `reflexive` 存档仍走旧解释器；这种兼容不意味着旧存档被迁移到了 v2。

## 完整材料、检索与私人边界

权限投影先于检索。一个位置不能通过方法、选择或视图的间接引用取得另一位置尚未共享的主体背景。含不可见材料的结构化历史视图整体不向该位置公开，避免分组标签和关系泄露私人组织。

`ResponseRecord.visibility` 可以是 `scope` 或 `shared`。前者只在来源作用域内可见；共享回应仍需满足其引用对象的可见条件，不能借“共享”绕过私人材料边界。生成正文中主动说出的内容可能进入共享材料，这是叙事行为，与系统泄露私人输入不同。

完整对象仅指**当前实验存档已有、且当前作用域有权限的对象**。本版不会自动打开原小说的 DOCX/EPUB，也不会从文件目录补读未导入的原文。没有用摘要替换已保存正文。

检索采用本地确定性的词项匹配和显式引用关联：英文数字词项、中文相邻双字项、连续子串匹配，以及 `related_to` 指定的关系过滤。它不使用外部嵌入服务，也不保证识别语义同义词。未指定 `limit` 时没有隐含的检索结果数量上限。

候选预览会标识截断；实际 `read` 和查询结果选入的材料使用完整值。v2 的程序查询发生在确定性编译期间，没有新增“模型边读边发工具调用”的循环。模型在本次提出查询后，查询结果可以进入随后采用该方法的生成输入。

## 一个窗口怎样推进

1. 保存窗口和策略版本，为人物冻结构想输入。
2. 人物基于同版输入并行提出正文、承接操作，以及可选的方法、采用变更和局部回应。
3. 在副本中验证并共同安装承接与方法反馈，保存实际构想选择。
4. 编译采用的方法，为人物冻结续延输入，生成并保存续延与选择证据。
5. 为启用的阅读冻结输入，各读轨独立形成正文及可选反馈。
6. 共同安装已接受的阅读反馈，处理待生效的停止采用，完成窗口。

**调度目前是影子模式。** 每个完整窗口仍执行全部人物构想、全部人物续延和全部启用阅读；若人物数为 P、启用阅读数为 R，正常无重试时是 `2P + R` 次生成调用。影子计划记录依赖、输入变化及继续原因，不据此省略任务，也未证明节省 Token。

承接贡献在 v2 按来源、目标、表达和角色分别更新。某来源没有更新的贡献继续存在；`withdraw` 显式撤回提交者自己的贡献。内核已可处理指定参与集合，但当前生产 Runner 仍提交所有人物。

阅读保留各自起点、焦点与历史；v2 当前读取其完整既有段落历史。跨读轨的相互影响通过共享材料、可见方法与回应发生，不自动汇总成唯一正确故事。完整历史也意味着长局上下文和费用会增长。

在未完成窗口中点击“停止采用”，v2 会排队到窗口完成后生效，当前冻结请求继续使用原输入。旧模式保持原有释放语义。

## 区分组织变化、请求变化与叙事改善

`plan_fingerprint` 记录执行过的方法定义及确切依赖。`input_fingerprint` 记录编译后的材料、规范化视图与组织指令，排除纯技术分组 ID。两者可能一个变化、另一个不变。

这个编译输入摘要不等于整个 HTTP 请求摘要。构想与阅读还具有各自的接口、历史等上下文；`RequestEnvelope.request_hash` 对提供方实际 JSON 投影作摘要，用来核对完整请求。逐次修复尝试保存自己的投影摘要和用量，不能用一次选择指纹替代请求证据。

“输入变化”说明程序影响了生成条件。“局部回应”说明生成者提出了一个解释。两者都不能直接证明文本更好、世界更连贯或意图已经涌现。

## 消融与配对干预

在技术面板底部选择采用位置和方法：

- “执行方法离线消融”在副本中移除采用并重新编译，返回前后输入比较，不保存新分支。
- “创建配对实验”从已完成的稳定窗口保存对照和干预两份存档。干预分支停止指定位置采用指定方法，对照分支保持原样。创建本身不生成，之后分别打开并推进。

两份分支保留共同起点摘要与干预记录。方法以后仍可能重新被采用，研究的是一次明确干预的后续轨迹。比较真实模型需要检查模型配置、请求证据和多次运行；一对不同段落不是语义因果证明。

创建时还会冻结代码与生成配置的签名。后续检测到程序、模型、输出参数或端点改变，会在调用前返回 `EXPERIMENT_CONFIGURATION_CHANGED`，需要按当前配置重新建立配对。签名不包含密钥，文档及网页不暴露端点。暂停请求的原输入与模型投影也会校验，配置漂移不会悄悄改写已保存的请求证据。

## 离线验证

```sh
.venv/bin/python scripts/verify_v2.py
.venv/bin/python scripts/verify_v2.py --windows 5
```

脚本只使用内置 `letters` 预设和确定性 `fixture`，直接创建临时数据库，不启动网页、不加载 `.env.local`、不调用付费 API。临时数据在结束时清除。`--windows` 必须是正整数，默认 3。

每个窗口核对完成状态、独立事件重放、请求证据及重新载入的语义状态。最终输出 JSON 汇总数量、零 Token 用量及通过的窗口数；不会输出材料原文、请求正文或原始异常。执行两个以上窗口时，还要求至少一条执行后果确实依赖已有回应。

脚本检查真实执行结果，所列数量随窗口和实现变化，不把方法层数或对象数量当作文学成绩。失败以固定检查标签退出；更细的恢复、隐私、方法类型与前端行为由测试套件覆盖。

## 当前边界与代码入口

尚未开放任意递归子模型作业、运行时新增基本操作、动态创建叙事位置、稀疏执行调度或自动判定叙事意图。没有训练新模型、修改神经注意力或读写 KV cache。有限字段格式、类型、来源权限和循环检测仍然生效；实验预算延续正整数或 `null` 不设限的语义。

对象与长文本使用内容寻址存储，事件和检查点仍保留完整执行证据。长局依然需要反复编译、检查和载入增长中的历史；本版没有把持久化改造成无限规模的流式数据库。

schema 5 的事件和已接受请求独立保存；每次检查点只打包新增事件、未封存请求及当前状态，窗口完成时回收不再被任何存档或事件引用的对象。物理去重不会使两个历史值共享可修改的内存对象。普通网页快照只返回请求摘要，完整输入保留在显式导出和读取接口。重建完整导出仍有成本，不等同流式导出。

| 工程入口 | 职责 |
|---|---|
| `backend/opentale/policy_types.py` | 操作类型、引用和视图结构 |
| `backend/opentale/policy_compiler.py` | 确定性求值、版本依赖及两类摘要 |
| `backend/opentale/object_store.py`、`retrieval.py` | 固定版本与权限过滤后的本地检索 |
| `backend/opentale/reflection.py` | 对象投影、安装、选择、视图和后果记录 |
| `backend/opentale/request_evidence.py`、`runner.py` | 请求冻结、阶段恢复和调用记账 |
| `backend/opentale/scheduler.py` | 影子依赖调度观察 |
| `frontend/src/components/ReflectionPanel.tsx` | 方法、实际选择与配对实验入口 |
| `scripts/verify_v2.py` | 临时数据库上的离线闭环验证 |
