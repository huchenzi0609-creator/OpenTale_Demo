# 模型输入分页、压缩与恢复

反身实验 v2 的世界可以积累比一次模型调用更多的材料与组织结构。程序保留完整世界；模型每次接收的输入则需要形成有限、可追溯的投影。本文说明当前投影版本、容量边界，以及部分阶段已经成功时的恢复方式。

## 单次上下文与累计预算

累计调用数、累计 token 与窗口数由实验存档控制，可以设为无限。模型单次请求仍有实际容量。提高累计 token 预算不能解决一次请求的 JSON 已经过大的问题。

同一段文字可能被许多材料位置、方法、视图和读轨引用。请求也可能包含大量短小的接口、关系和目录行；即使正文已经很短，结构本身仍可能超过容量。因此，当前处理同时考虑文字、结构、接口表和动态 schema。

输入整理是本地确定性操作，不调用额外的摘要模型，不改变累计预算，也不自动开始新的世界窗口。

## 完整输入与本次页面

三个层次分别保存：

1. **完整材料与冻结 frame。** 保留此次作业的原文、原视图、对象版本与权限，供恢复、校验和回放使用。
2. **本次模型页面。** 从冻结 frame 构造有限输入，允许去重、摘录、折叠和分页。省略的结构或正文必须标明，不能宣称全部原材料已经进入模型。
3. **实际请求证据。** 每次发送的完整请求体、投影版本和 request hash 独立保存；accepted 结果与事件相互校验。

分页不会用删节内容覆盖人物 Markdown、共享表达、正文、方法程序或原视图。原选材数量与本页呈现数量可能不同，这是需要展示与验证的事实。

## 当前 v3 投影

新投影标识为 `provider-json-v3-bounded`，算法标识为 `source-pages-v1`，实现在 `providers/context_bounded.py`。

处理顺序以减少信息损失为先：能够去除的完全重复行先去重；重复文字与元信息在划算时共享表示；仍然过大的内容采用有来源的摘录和结构页面。材料出现的位置和作用、候选接口、选中视图与阅读历史分别记录其投影情况。

页面包含有限的可见接口。整数身份仍对应原冻结请求，输出校验使用同一份页面能力表 `context_capabilities`：对象、作用域、路由、阅读焦点、各焦点的表达以及历史引用，都必须属于本次实际暴露的接口。分页不能扩大私人资料权限，也不能把某个编号悄悄改指另一个对象。

当完整树、候选目录或历史本身过大时，可以保留结构概览和部分页面。页面记录原集合大小、可见位置、省略数量与来源摘要 hash。没有进入本页的材料仍在世界中，后续可以经合法的读取／检索方法重新选择。

系统最终检查的是**系统提示、动态 schema 和用户 JSON 的实际合计长度**。只缩短正文，或者固定尝试几轮压缩，都不足以满足这一条件。格式修复说明也需要预留输入空间。

## 摘录并非语义无损摘要

保留的文本片段能追溯到原文字段及字符区间，系统不会将来源间的空隙伪装成连续原文。片段省略可能损失关键转折；结构页面也可能暂时隐藏原视图的重要关系。来源正确不等于语义完整。

这些内容由确定性的输入整理产生，不是另一个模型理解全文后写出的经过核验的摘要。极长语句可能需要字符区间摘录；相应标记提醒模型片段边界之外仍有语境。正文输出继续使用自然语言，不应包含页面编号、来源 hash 或技术解释。

完整内容的存在也不意味着模型会在同一次调用内自动取回省略部分。当前读取与检索要通过方法或本地对象接口实际进行。

## 完整内容的取回

本地接口继续服从作用域过滤：

- `GET /api/runs/{run_id}/objects?scope_id=...&query=...`：检索该位置可见的对象。
- `GET /api/runs/{run_id}/object?scope_id=...&object_id=...`：取得该位置可见对象的完整内容。

方法中的精确旧版本引用由对象解析器处理。分页不能让另一人物获取本来不可见的私人背景，也不会将“未出现在当前页面”解释为“原文不存在”。

## 配置与统计

`OPENTALE_CONTEXT_TARGET_CHARS` 默认 **96000**，单位是字符，不是 token。它控制单次投影目标；累计预算和模型输出参数各自保持原来的意义。配置值没有人为的累计预算上限，但一次实际请求仍须满足传输容量。

系统优先保留完整内容：去重后的全量表示能够安全容纳时，即使超过柔性目标也可以保留，并标记 `within_target=false`。必须分页时，目标用于分配工作页面空间；过小的目标也需要让位给合法接口与必要工作内容。它不是严格的发送长度开关。

压缩统计位于实际请求的用户 JSON 中的 `context_compaction`，并进入请求证据摘要：

| 字段 | 含义 |
| --- | --- |
| `algorithm` / `projection_version` | 实际使用的算法和投影版本 |
| `input_chars` / `output_chars` / `target_chars` | 原输入、基础投影与目标的字符量 |
| `material_occurrences` / `material_occurrences_visible` | 原材料出现次数与本页呈现次数 |
| `candidate_objects` / `candidate_objects_visible` | 原候选对象数量与本页候选数量 |
| `history_segments` / `history_segments_visible` | 原阅读历史数量与本页历史数量 |
| `original_text_chars` / `retained_text_chars` / `omitted_text_chars` | 文本统计，需结合页面的来源范围解释 |
| `lossy` / `structure_excerpted` | 文字省略与结构摘录状态，不能只看其中一个字段判断是否完整 |
| `pages` | 各集合的路径、原大小、可见位置、省略数量和来源摘要 |
| `within_target` | 基础投影是否落在目标内 |

格式修复提示可能增加最终长度，因此逐次尝试另记实际 `request_chars`。它不一定等于基础投影的 `output_chars`。原材料数量仍很大而页面数量较小，是分页生效的正常表现，不能把前者误称为实际发送量。

## 旧版本保持原样

`provider-json-v1` 保留最初的请求表示；`provider-json-v2-context` 继续使用冻结在 `providers/context.py` 的旧算法。旧 v2 的 `source-excerpts-v1` 会共享文字并保留全部选中结构，但没有对任意输入提供容量保证。

例如：大量中等长度的首尾句可能始终超过摘录额度；成千上万个短历史段的文本池元数据可能比正文更大；大量互异 group 或候选引用不能靠去重缩小。v3 的结构分页专门处理这些情况。修改默认版本不会把旧请求冒充为新算法生成的输入。

## 部分成功时怎样恢复

每个已冻结请求都有投影版本。恢复分两种情况：

1. **前置投影拒绝，尚无 envelope。** 对原冻结 frame 使用新投影；已经接受的构想、续延或读轨结果跳过，只补做缺失作业。
2. **已有 envelope 和尝试记录，但尚未接受结果。** 适配器继续使用该 envelope 的旧版本，保持原 request hash 与 frame hash。新程序不能覆盖这些历史值。

本次升级没有实现替代 envelope 的协议。如果旧未接受请求本身需要切换投影版本，必须通过显式的新请求／干预过程处理；不能删除旧证据、清空窗口，或把压缩变化伪装成格式修复。

一个典型恢复点是：8 个位置已经完成构想与续延，共 16 次作业已接受，两条读轨却在发送前被拒绝。升级后只补做两次阅读，前 16 份结果、其请求 hash 和原计费记录保持不变。

## 费用与证据

本地投影拒绝发生在网络发送之前，不增加模型调用数，不预留 token，也不形成未知消耗。重复点击恢复不能因此重复计算已接受作业。

已经真正发出的请求仍按原规则记账：可信用量记实际数值；网络中断且用量未知时保留未知占用。压缩不能把历史费用清零。

证据校验分别验证冻结 frame、逐次实际投影、来源片段／页面，以及 accepted 结果与事件。语义回放使用原冻结输入和已接受的关系操作，不重新调用模型。严格配对实验另有程序与配置签名；普通实验能恢复，不代表升级前后仍满足同条件对照。

## 离线验收范围

`tests/test_context_bounded_runtime.py` 使用完整 DeepSeek 请求构造流程检查四类合成极端输入：600 份中长双句材料、10000 个空分组、6000 个单字历史段、4000 个带大引用数组的候选对象。检查包括最终系统提示／schema／用户输入合计容量、来源与分页标记、原 frame 不变。

当前合成案例的实际请求测量如下，均包含系统提示、动态 schema 与用户 JSON：

| 合成输入 | 最终请求字符数 | 本页呈现 |
| --- | ---: | --- |
| 600 份中长双句材料 | 59473 | 46 个材料出现位置，原 600 个仍在冻结输入中 |
| 10000 个空分组 | 16318 | 结构页面明确省略大量分组，保留当前组织指令与材料 |
| 6000 个单字历史段 | 91331 | 166 段历史，编号继续指向原历史位置 |
| 4000 个大引用候选加 4 个基础候选 | 81707 | 288 个候选，原 4004 个仍在冻结输入中 |

这些数值是当前测试版本的测量结果，后续提示或 schema 变化可能改变字符量。测试约束最终容量与证据有效性，不把某个固定压缩比例视为保证。

同文件还覆盖 8 个位置的 16 次作业已接受、两条阅读前置拒绝的恢复情形，验证只补做两次阅读，既有证据与使用量保留，保存重载及回放通过。

旧 v2 适配器另有升级前捕获的合成请求 hash 金样，确保保留的不只是旧版本名称，还包括其确切系统提示、schema 和请求表示。

`tests/test_context_runtime.py` 保留三个模式的本地拒绝记账、部分构想恢复和旧请求版本适配测试。所有这些检查都使用合成材料、离线夹具或本地模拟传输，不使用私人实验正文和真实 API。它们验证工程边界，不能证明分页后文学质量或叙事含义完全保持。
