# 方法的实际调用、评议与继续生成

2026-10-10，v0.6.3，实验分支，schema 6。新工作冻结 `work_protocol: growth-work-v2`；旧已接受阶段和原始正文保持，按其冻结资料继续安装。

## 问题证据

真实读轨的第十五个动作已经被适配器接纳：修订依据中有一条已交付的公开关联边。适配器允许连接和组织句柄，宿主却只查节点、方法、回应、试写、访问和阅读六类。合法依据因此被判不可见，accepted 缓存又使重试永远复用同一决定。

另一读轨的三次格式失败只保存通用 `SCHEMA_INVALID`，无法准确还原坏字段。确定存在的另一个缺口是访问与阅读成品进入了句柄目录，却无法作为 `read_page` 的类型。此次补齐并保存安全字段反馈，没有根据输出 Token 数猜测返回内容。

五窗口的 233 个成功动作中，改版 11 次、试写 18 次、发布 14 次；查看、分页、应用、采用共 149 次，占约 64%，相同操作重复出现。方法沿革最大深度 3，回应引用回应已有 7 层。因此增加引用链并不能独立解决停滞，需要实际使用方法及评议，减少重复取得资料，让结果改变组织和判断。

## 同源、精确的对象目录

`growth_capabilities.py` 是模型验证与宿主的共同边界。新 frame 在作用域校验后冻结 `{kind, object_id, version}`，支持 `node/method/trial/response/visit/passage/link/view`。旧 frame 只从已交付目录、页面和结构推导。自然语言正文、ID 前缀及未交付的私人依赖不会产生权限。

字符串句柄必须唯一。多版本时使用 `input_refs/about_refs`、`method_version`、`trial_version`、分页 `version` 或评议方法版本明确选择。宿主按同一解析器取得类型、版本，再检查作用域。分页和引用覆盖八类有效对象。

失败尝试的 `validation_feedback` 只含受限字段和原因，例如 `HANDLE_UNKNOWN`、`HANDLE_VERSION_MISMATCH`。拒绝文本、秘密和隐藏推理不进诊断。有限格式修复沿用原输入和预算。完全未变的合法修订复用原版本并返回无变化收据。

## 方法成为执行材料

原 `source_refs` 表达改版依据，不会自动执行父方法或将整条祖先链灌回模型。新程序有明确操作：

| 字段 | 实际作用 |
| --- | --- |
| `inputs: ObjectRef[]` | 将方法、组织、回应、试写、阅读等精确对象作为当前材料 |
| `calls: [{method_ref, input_refs}]` | 调用保存的方法版本，先执行其组织，再把结果传给上层 |

组织使用显式工作栈；有限调用图可持续加深。子方法结果进入上层输入和缺省选材，父显式 `node_ids` 决定根输出。视图 `members` 保留整体调用材料，`execution.root_output_refs` 表达根实际选材。一般对象保持类型，方法定义不会伪装成世界事件。

执行记录包含调用帧、精确输入输出、指令引用、实际深度和挂起信息。相同方法及输入复用完成结果，避免密集菱形指数扩张；当前路径循环留下挂起帧供检查和改写。挂起的当前组织不能直接进入试写/呈现。旧非复合视图 ID、值和哈希保持。

后续生成和评议获得实际组织与材料页面。阅读只以真实访问范围作为事件来源，额外方法/回应决定呈现方式。较大执行计划交付有限帧和指令窗口，明确标记部分与完整数量；全文保留在视图，仍可分页读。

## 高频评议与持续改版

`reflect` 选择精确评议方法及对象，调用 `review`，保存实际效果、判断方式和下一次可执行差异。省略对象时可评议方法自身；也可评议此前评议及其标准，再用作方法输入、组合或改版依据。

新协议每次 DeepSeek 试写/呈现后自动评议一次结果及所用方法，通常增加一次调用。评议单独冻结、计账和恢复；已有草稿及 accepted 评议复用。用户的现有预算继续有效，历史冻结工作不追溯补做。

模型可继续评议、修改、试用或发布，阶数由实际问题展开。提示会积极把前一份评议及判断方式作为下一次检查对象，要求变化进入选材、关系组织、行动后果或阅读重点。

完整方法进入缓存。同一读取、相同组织或同一采用返回 `changed: false`，连续无变化 I/O 暂从下一菜单移除，材料变化后重新开放。模型可以复用资料转向实际评议与新构造。无变化修订也复用原版本，避免把查看/安装当作进步。

## 分别记录三种层次

| 指标 | 说明 | 独立不能证明 |
| --- | --- | --- |
| 版本沿革 | 方法如何改写 | 实际调用、高阶判断 |
| `max_call_depth` 与完成/复用帧 | 声明式组合怎样实际执行 | 认知深度、文学效果 |
| `review_order` | 实际评议针对前一份实际评议，继续时加一 | 判断质量、意图价值 |

自动结果评议从一阶开始。普通 `respond` 或历史引用链不自动取得阶次。会话保存最近评议与最高已观察阶次，回应保存精确对象、方法和请求。技术指标放在方法/诊断页，正文保持叙述。

## 验证及边界

开发验证全程离线，覆盖类型一致、连接/组织依据、精确历史版本、私人边界、分页、安全反馈、真实组合输入、连续评议、自动评议及预算中断。已接受评议安装中断后复用结果，草稿和阅读不再计费。1050 层栈及密集图验证证明有限程序执行能力。

真实失败存档的只读副本成功安装原关联边修订，新增调用为 0，状态重建及内核回放通过。历史格式失败缺少精确字段证据，后续异常将留下安全诊断。模型依然可能输出不合要求的内容，恢复点继续保留。

方法真正进入输入、调用结果改变组织、实际评议继续成为对象，为高阶意图提供了执行通道。新的叙事方向需要后续真实样本评估：评议改变了什么、方法怎样采用、下一段生活是否产生不同后果。程序层数不替代这些判断。
